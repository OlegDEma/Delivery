# Delivery — контекст проєкту

**Перед роботою прочитай `.claude/context/00-START-HERE.md`** — там зібрано весь
контекст проєкту (стан по датах ТЗ, робочий цикл, середовище для Windows і macOS,
протокол спілкування з клієнтом, плейбук UI-тестів, незакриті хвости).

Глибші технічні довідники — у `.claude/skills/delivery-project/references/`.

## Три правила, які порушувати не можна

1. **Не казати «готово» без живої перевірки в UI.** `tsc` і `build` — не доказ.
   Якщо щось не перевірено — сказати прямо, що саме.
2. **Коментарі в коді — українською** (з посиланням на дату ТЗ), **ідентифікатори —
   англійською**. Відповіді користувачу — українською.
3. **Не ламати те, що працює.** Локальна розробка йде проти прод-БД — тестові
   зміни в даних одразу відкочувати.

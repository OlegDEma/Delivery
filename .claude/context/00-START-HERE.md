# Delivery — контекст-пак (читати ПЕРШИМ на новій машині)

Цей каталог — «памʼять проєкту», перенесена в git, щоб Claude на **будь-якій машині**
(Windows-ПК або Mac) мав однаковий контекст. Усе, що раніше жило лише в локальній
памʼяті Claude на ПК, тепер тут.

## Що прочитати і в якому порядку

| # | Файл | Про що |
|---|---|---|
| 1 | `01-current-state.md` | Де ми зараз: що зроблено по датах ТЗ, що на проді |
| 2 | `02-workflow.md` | Як ми працюємо: цикл ТЗ → код → живий тест → пуш → коментар клієнту |
| 3 | `03-environment.md` | Запуск на **Windows і macOS**, БД, деплой, пастки середовища |
| 4 | `04-tz-and-client.md` | Де лежить ТЗ, як читати, як відписувати клієнту в коментарях |
| 5 | `05-ui-testing.md` | Як тестувати в реальному браузері (і чого не робити) |
| 6 | `06-open-items.md` | Незакриті хвости — з чого починати |

Технічні довідники (глибше по коду) — у сусідньому каталозі
`.claude/skills/delivery-project/references/`: модель даних, тарифи, ролі, статуси,
пастки, SMS-рахунки, аудит ТЗ.

## Правила, які не можна порушувати (коротко)

1. **Не казати «готово», поки не перевірено наживо в UI.** Прогнати `tsc`/`build` —
   недостатньо. Якщо щось не перевірено — сказати прямо, що саме.
2. **Коментар клієнту в ТЗ ставимо лише після реальної перевірки** (див. `04`).
3. **Коментарі в коді — українською, ідентифікатори — англійською.**
4. **Не ламати те, що працює.** Кожна зміна — з посиланням на дату ТЗ у коментарі.
5. **Відповідати користувачу українською.**

## Чого тут НЕМАЄ (і не буде)

- `.env` та будь-які секрети — не комітяться (`.gitignore`). На новій машині
  скопіювати `.env` вручну з ПК.
- Паролі тестових акаунтів — питати в Олега.
- Авторизація Google-конектора та сесії браузера — прив'язані до машини,
  налаштовуються заново.

## Перший запуск на Mac — по кроках

```bash
git clone https://github.com/OlegDEma/Delivery.git && cd Delivery
npm install
```

1. Скопіювати `.env` з Windows-машини (`D:\Delivery\.env`) у корінь клону.
2. `npm run dev` → відкрити http://localhost:3000/login → залогінитись.
3. У Claude сказати: **«прочитай .claude/context і скажи, на чому ми зупинились»**.
4. Перевірити доступ до ТЗ: Google Doc має бути розшарений на той Google-акаунт,
   який підключено конектором саме на Mac (інакше — «файл не знайдено»).
5. Перший `git push` попросить логін GitHub (macOS keychain) — далі працює само.

## Паралельна робота на двох машинах

- Перед роботою: `git pull --rebase`. Після: одразу пушити, щоб друга машина
  не розійшлась (репо містить згенерований Prisma-клієнт — конфлікти в
  `src/generated/prisma` розвʼязуються як `npx prisma generate` після мержу).
- **База одна на обох машинах** (прод-Supabase) — паралельні тести можуть
  заважати одне одному. Домовлятись, хто зараз тестує.
- Контекст-пак — жива документація: якщо щось дізнались/змінили,
  оновити відповідний файл у `.claude/context/` тим самим комітом.

## 3. P0 — КРИТИЧНО: прод-БД відкрита для читання і видалення всім

**Перевірено особисто** (01.10), публічним anon-ключем, який лежить у JS сайту:

```
GET  /rest/v1/parcels?select=id&limit=1   → 200  [{"id":"c9966082-…"}]
GET  /rest/v1/clients?select=id&limit=1   → 200  [{"id":"67861211-…"}]
GET  /rest/v1/profiles?select=id&limit=1  → 200  [{"id":"6379fa19-…"}]
DELETE /rest/v1/parcels?id=eq.<uuid>      → 204  (права є; рядок не існував, тому 0 змін)
```

Стан БД: **RLS увімкнено на 0 із 25 таблиць, політик 0**; ролі `anon` і `authenticated`
мають `SELECT, INSERT, UPDATE, DELETE, TRUNCATE` на таблицях (перевірено на `clients`).

**Наслідки:** будь-хто з інтернету може викачати всіх клієнтів (ПІБ, телефони, адреси —
це EU-персональні дані, GDPR) і **видалити будь-який рядок**. Це також робоча версія
відповіді на питання «куди могли зникнути дані» на майбутнє.

**Фікс безпечний** (перевірено): Prisma підключається як `postgres` з `rolbypassrls=true`,
тож увімкнення RLS **не зламає жодного API-роуту**. Єдине, що читає таблиці через
supabase-js із сесією користувача — `profiles` у 4 місцях (`login/page.tsx:59`,
`reset-password/page.tsx:63`, `hooks/use-auth.ts:31`, `supabase/middleware.ts:166`),
тому для `profiles` потрібна політика «своя стрічка».

Міграція (не застосовано — чекає рішення):
```sql
-- 1) RLS на всі таблиці public (без політик = anon/authenticated не бачать нічого)
ALTER TABLE public.parcels ENABLE ROW LEVEL SECURITY;  -- і так для всіх 25
-- 2) профіль: користувач читає ЛИШЕ свій рядок (потрібно для логіну і middleware)
CREATE POLICY profiles_self_select ON public.profiles FOR SELECT TO authenticated
  USING (auth.uid() = id);
-- 3) (додатково) прибрати зайві гранти
REVOKE ALL ON ALL TABLES IN SCHEMA public FROM anon, authenticated;
GRANT SELECT ON public.profiles TO authenticated;
```
Після застосування перевірити: anon GET → `[]`/401, логін staff і клієнта працює.

## 9. Доповнення після останніх аудитів (перевірено особисто)

**Скарга 28.09 п.3 «не використовує мінімальну оплату» — доказ у цифрах.**
Посилка №5: 0.1 кг до пункту видачі у Відні = **0.26 €**. Мінімум не діє, бо
`isPickupPoint` у розрахунку означає лише спосіб передачі ВІДПРАВНИКА в EU→UA
(`parcel-creation.ts:261-265`), а не «Пункт видачі» Отримувача. Тариф має поле
`pickup_point_price` (NL 15 / AT 10) — тобто задум був. Аудит посилається на старі
розділи ТЗ (E49/E50/E54 «при самостійному отриманні клієнтом на Пункті збору»),
але **я цього тексту в наших довідниках не знайшов** — тож суму підтверджує клієнт.
Фікс (4 місця): `isPickupPoint = … || receiverDeliveryMethod === 'pickup_point'`.

**Скарга 28.09 п.2 (помилка у даних Відправника) — два кандидати:**
1. `api/clients/route.ts:153` — створення клієнта з уже наявним телефоном дає 409
   «Клієнт з таким номером вже існує» **без** `conflictClientId`, тому форма лише
   показує помилку і оператор у тупику. Для РЕДАГУВАННЯ resolve-to-owner є
   (`client-create-form.tsx:384`), для створення — ні. Клієнт уже скаржився на цей
   клас 15.07 — це збігається з його «це вже було».
2. `senderCity` без `required` у клієнтській формі → назовні летить сирий текст
   `senderCity: Обов'язкове поле`.

**Клієнтські замовлення ніколи не привʼязуються до рейсу** (`orders/route.ts:208`,
`tripId: null`; ТЗ E55 «автопривʼязка до найближчого рейсу» не реалізована) — тому
посилки клієнтів не потрапляють ні в Маршрути, ні в «Мої посилки» водія. Це накладається
на скаргу п.5.

**Неузгодженості тарифів:** `insurance_threshold=25` у БД проти 50 у коді (поле мертве);
у NL→UA лежить ігнорована `weight_custom_factual_fraction=0.4` при `weight_type='average'`;
для Німеччини тарифу немає взагалі, хоч форма пропонує DE (клієнт бачить «Вартість буде
розрахована працівником»); після PATCH зникає мінімум «туди-сюди» (`isBothDirections:false`).

**Скарга 28.09 п.1 — відтворено в браузері (13-й аудит).** Справжній компонент +
base-ui Dialog 1.3.0 + React 19.2.4 у Chromium: після кліку `href=#`, `target=null`,
подія `hashchange`, застосунок не відкрився; тости «текст скопійовано» і «відмічено як
надіслане» з'явились. З правкою `setTimeout(() => setPending(null), 400)` href лишається
`https://wa.me/…`, `target=_blank`. **✅ ВИПРАВЛЕНО** в `party-share-buttons.tsx` і
`passenger-share-buttons.tsx` (tsc і eslint чисті, не запушено).

## Що перевіряти замість скріншотів

Скріншот показує «щось намальовано», але не доводить логіку. Надійніше — JS-заміри
через браузерний інструмент:

- позиції/вирівнювання: `getBoundingClientRect()` (напр., два рядки рейсу мали
  однаковий `left` → довело вирівнювання)
- скрол: `window.scrollY` до/після + `maxScroll` (щоб не переплутати «не спрацювало»
  з «сторінка вже внизу»)
- дозволи: HTTP-код `fetch` до API (403 → 200 після фіксу)
- дані: прямий `fetch('/api/...')` і порівняння полів

## Пастки браузерного тесту

1. **Вкладка автоматизації `hidden`** → `requestAnimationFrame` призупинено,
   `scrollIntoView({behavior:'smooth'})` не працює. Тому в коді використовуємо
   `setTimeout` + `behavior:'auto'` — і надійніше для юзера, і перевірювано.
2. **Нативні `confirm()`/`alert()` блокують автоматизацію** (CDP зависає на 30 с).
   Обхід у тесті: `window.confirm = () => true` перед кліком.
3. **shadcn `Select` і `Checkbox`:** клік по `ref` часто не реєструється —
   клікати **по координатах** (скріншот → координата опції). Перевіряти результат
   читанням значення, а не припускати.
4. **Refs зсуваються** після кожного умовного ре-рендеру — перечитувати сторінку.
5. **Довгі `await` через навігацію** ламають виконання скрипта
   («Inspected target navigated») — розбивати на два виклики.
6. **Програмний клік по `<a>` блокується як popup** — тому кнопка «надіслати»
   в месенджер зроблена справжнім `<a href>`, а не `window.open` після `await`.
